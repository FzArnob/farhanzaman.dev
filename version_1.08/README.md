# fz.is-best.net — version 1.07

A React + TypeScript SPA. 1.07 moved the data out of MySQL and into `data/profile.json`;
1.08 rebuilt the whole front of the site around a scroll-reveal motion system
(see `motion-design.md`). The data and the API contract are unchanged.

```
version_1.08/
├── data/                 profile.json + gaming_videos.json  (served at /data)
├── frontend/             React + TypeScript + Vite, builds to plain html/js/css
├── backend/              PHP: visitor tracking, contact messages, gaming refresh
├── admin/                PHP editor for profile.json
├── build/                build.bat -> release_<timestamp>/
└── old/                  the previous PHP-routed version, untouched
```

## What changed from 1.07

The redesign is documented in full in `motion-design.md`. The short version:

| 1.07 | 1.08 |
| --- | --- |
| Beating-logo pre-loader on a fixed 1s + font wait, every page view | `GlitchLoader` — the logo's own two colour channels tear apart and resolve; only appears if the load is actually slow (140ms grace, 700ms minimum once shown) |
| Particle canvas mounted inside the hero only | one `ParticleField` canvas behind the whole site, particle-capped, spatial-hash linked, DPR-capped, with a periodic packet-burst glitch |
| PNG cursor image; implode trail on the hero only | native cursor hidden site-wide (except `/gaming`), teal probe + spring-lagged magenta ring + pooled trail; native cursors restored on touch |
| `wobbleAnimation()` rewrote text nodes into per-letter spans on every scroll event | `data-reveal` engine — one IntersectionObserver, CSS-owned transitions, reveal-once. Per-letter wobble is hover/click only now |
| `TagCloud` sphere of expertise names, rebuilt on every resize | `SkillSphere` — own Fibonacci sphere, assembles out of the particle field, surfaces `level` / `duration` / `description` on lock-on. TagCloud dependency dropped |
| Certificates in a flat row | `Achievements` constellation — nodes linked by measured SVG lines in the particle-network style |
| `animate-left/right/top/bottom` animated `margin-*` by 300px | same class names, `translate` instead — no reflow per frame |
| `*:focus { outline: none !important }` | `:focus-visible` rings (mandatory once the cursor is hidden) |
| `user-scalable=no` in the viewport meta | removed (WCAG 1.4.4) |
| `TitilliumWeb-Regular.ttf` (57 kB), `icons.ttf` (3.9 kB), no `font-display` | `.woff2` (20 kB / 2.2 kB) preloaded, `font-display: swap` — the `.ttf` files stay as fallback |
| `transition: all 0.5s` on ~24 theme selectors | scoped to the properties those classes actually set |
| Page background on `body`/`.main-page` | on `html`, so the particle canvas at `z-index: -1` shows through the whole document |

Added: `motion` 13.1.0 (`animate` from `motion/mini`, plus `inView`, `scroll`, `stagger`).
Removed: `TagCloud`. Net effect on the wire is **-20.6 kB** — the font conversion more than
pays for the new JS.

## data/

The single source of truth for page content. `profile.json` holds exactly what
`result.profile` held before (`info`, `educations`, `experiences`, `expertises`,
`skills`, `achievements`, `projects`, `gallery`). Edit it by hand — nothing
regenerates it.

`gaming_videos.json` is regenerated by `backend/api/update-gaming-videos.php`.

### The domain lives here

`info.website_base_url` and `info.website_domain_name` are the only place the
site's own address is written. Change them and everything follows:

| Consumer | Uses |
| --- | --- |
| API host (`track-visitor`, `send-direct-message`) | `website_base_url` + `/backend/api` |
| Footer copyright | `website_domain_name` |
| 403 / 404 / 500 page link | `website_base_url`, `website_domain_name` |
| `profile_id` sent with every request | `info.profile_id` |

Any string in `profile.json` may also contain `{{base_url}}` or `{{domain}}`;
both are substituted when the file is loaded. The three self-hosted project
links use it:

```json
"live_url": "{{base_url}}/tms/tms.zip"
"live_url": "{{base_url}}/examiner"
"live_url": "{{base_url}}/spaceninja"
```

## frontend/

```
npm install
npm run dev        # http://localhost:3050, serves ../data at /data
npm run build      # -> dist/ (html + js + css + view/ assets + data/)
```

`dist/` is the deployable folder. It contains `.htaccess` with the SPA rewrite,
the HTTPS redirect and the `ErrorDocument` mappings.

The API host is derived from `website_base_url` in `data/profile.json`. For local
work against a XAMPP backend, set `VITE_API_HOST` in `.env` (see `.env.example`) —
it only applies to `npm run dev`, so a production build can never ship a
localhost URL.

### Layout

```
src/
├── main.tsx              applies the theme, mounts the router
├── App.tsx               loads profile.json, then the routes
├── data/                 profile fetch + context
├── hooks/                page reveal, viewport size, document title
├── lib/                  api, tracking vocabulary, theme, wobble, particle field
├── lib/motion/           tokens, shared rAF loop, reveal engine, FLIP
├── components/           one folder per reusable piece of the page
├── pages/                one folder per route
└── styles/               app.css split into ordered partials + 24-motion.css
```

`styles/index.css` imports the partials in the original file order, so the
inherited cascade is unchanged; `24-motion.css` is imported last and holds the
whole motion system (tokens, reveal variants, the decode glitch, the cursor,
focus rings) plus the corrections the redesign needed. The two theme sheets stay
separate files in `public/view/css/theme/` because the theme toggle swaps a
`<link>` element, exactly as before.

### Motion

Three files carry the system, and everything else uses them:

| File | Job |
| --- | --- |
| `lib/motion/tokens.ts` | the duration / easing / stagger table, mirrored as CSS vars in `24-motion.css` |
| `lib/motion/raf.ts` | **one** `requestAnimationFrame` loop shared by the particle field, the cursor and the sphere, plus a read/write batcher |
| `lib/motion/reveal.ts` | scans `[data-reveal]`, observes with `inView`, flips `data-revealed`; CSS owns the transition |

`prefers-reduced-motion` is a complete path, not an afterthought: the field draws
one static frame, the trail and decode are off, and every reveal applies its end
state immediately. Nothing is ever left invisible.

Page-scoped CSS lives with its page: `pages/Gaming/gaming.css` is injected only
while the gaming route is mounted (it overrides global scrollbar and logo rules),
and `pages/Error/error.css` is class-prefixed so it cannot collide with app.css.

## backend/

Three endpoints, no profile tables, no cron jobs.

| Endpoint | Method | Purpose |
| --- | --- | --- |
| `api/track-visitor.php` | POST JSON | one visitor action → `visitor_tracking` (+ `visitor_locations`) |
| `api/send-direct-message.php` | POST | contact form → `direct_messages` |
| `api/update-gaming-videos.php` | GET/POST | rebuilds `data/gaming_videos.json` from the YouTube API |

```
backend/
├── api/            request handling only
├── controllers/    response shaping
├── models/         SQL and external API calls
├── lib/            Http helpers, mysqli connection
├── config/         db credentials, api keys, paths
└── sql/ddl/schema.sql
```

Run `sql/ddl/schema.sql` to create the three tables. The tag vocabulary written
into `visitor_tracking` is documented at the bottom of that file.

Because there is no cron job any more, a failed IP geolocation is retried on a
later visit: `visitor_locations.tracked_date` now records the last lookup
*attempt*, and an untracked IP is looked up again after `LOCATION_RETRY_HOURS`.

`update-gaming-videos.php` writes into `../../data/`, so on the server the
backend folder must sit next to the deployed `data/` folder:

```
webroot/
├── index.html, assets/, view/, data/   ← contents of frontend/dist
└── backend/                            ← contents of backend/
```

Set `UPDATE_TOKEN` in the environment to require `?token=…` on the refresh
endpoint. `DB_HOST`, `DB_USERNAME`, `DB_PASSWORD`, `DB_DATABASE`,
`GEOAPIFY_API_KEY` and `YOUTUBE_API_KEY` can all be overridden the same way.

## admin/

A small PHP editor for `data/profile.json` — no database, no build step. Open
`/admin/` and sign in with the single hard coded password (stored in
`index.php` as a bcrypt hash and checked with `password_verify`).

```
admin/
├── index.php       auth, save handling, entry point
├── lib/schema.php  every editable field, in one array
├── lib/builder.php POST -> profile array, plus validation
├── lib/render.php  form rendering
├── lib/ProfileStore.php  load, backup, atomic write
├── views/          login and editor markup
└── assets/         admin.css, admin.js
```

What it does:

- Tabbed editor for all eight sections, add / edit / remove on every list,
  including the nested media rows inside a project.
- Collapsible cards with live titles, a per-section filter box and an
  unsaved-changes guard (Ctrl/Cmd+S saves).
- Untouched columns survive a save: `created_date`, `delete_flag`,
  `fk_profile_id` and ids are carried over, and new rows get the next free id
  plus the same key order as existing ones.
- Validation runs before anything is written — on failure nothing is saved and
  what you typed is kept on screen.
- Every save first copies the current file to `data/backups/profile-<stamp>.json`
  (last 20 kept), then writes atomically via a temp file and rename.

**Adding a field** means adding one line to `lib/schema.php`; the form, the
template for new rows, validation and saving all follow from it.

Security is deliberately minimal, matching the ask: one bcrypt-hashed password,
a session cookie scoped to `/admin`, CSRF tokens on both forms, five attempts
then a five minute lockout, and a one hour idle timeout. It is only as private
as the URL — keep HTTPS on (the root `.htaccess` forces it) and change the hash
if the password ever leaks. To change the password, replace
`ADMIN_PASSWORD_HASH` with the output of:

```
php -r "echo password_hash('your new password', PASSWORD_BCRYPT);"
```

## build/

`build\build.bat` produces one deployable folder containing the whole site.

```
build\build.bat                  full build, reinstalls node_modules with npm ci
build\build.bat --skip-install   reuse the existing node_modules
```

Output — `build/release_<timestamp>/`, laid out exactly as the web root:

```
release_20260804-172120/
├── index.html  assets/  view/  .htaccess   the UI, with the SPA rewrite
├── data/                                   profile.json, gaming_videos.json
├── backend/                                APIs
├── admin/                                  content editor
└── DEPLOY.txt                              build stamp, git commit, deploy notes
```

The script fails loudly rather than shipping something broken. It checks node and
npm are present, that all four source folders and `public/.htaccess` exist,
rebuilds `dist/` from scratch in production mode, then verifies: `index.html`,
`.htaccess` **containing the SPA rewrite**, `data/*.json` and `view/static`
assets are all present; **no localhost URL leaked into the JS bundle**; every
required backend and admin file made it across; and every PHP file in the
release parses (`php -l`).

`data/backups/` and stray `.env` / `*.log` / `*.map` files are excluded from the
release.

### Production config

`build/config/` is an overlay copied over the release **after** `backend/` and
`admin/`, so the working tree keeps your local settings while the release gets
production ones:

```
build/config/backend/config/configDatabase.php  ->  release/backend/config/configDatabase.php
```

Drop any other file there at the same relative path to override it — e.g.
`admin/index.php` for a different password hash. The build warns if the shipped
database config still points at localhost.

`release_*/` is gitignored.

## Visitor actions

The 1.06 tags are unchanged. 1.07 additionally tracks: social profile links,
certificate badges, footer credit, mobile menu toggle, photo viewer close /
zoom / thumbnail select, project live & source links, project media, copying a
contact detail, gaming video clicks, gaming sort filter, Discord, gaming
platform links, scroll depth milestones (25/50/75/100) and time spent on a page.
The full list lives in `frontend/src/lib/sync.ts` and is mirrored in
`backend/sql/ddl/schema.sql`.
